## Stored receipts and creator kinds

One strict parser — `parseStoredChannelSubmitReceipt` and `parseStoredChannelCreateReceipt` in core — serves the mutation receipt probe and the non-migrating replay-only inspection alike: the envelope and every nested object carry exactly their closed key sets, no body or private content field appears, the stored semantic bounds are re-validated without normalization (handle, title, context, and provenance rules; the normalized creation title must equal its stored form; the creation main's native provenance is exactly empty), the original submission decision state (unhandled, version 1, null handling fields) and the original creation view (open, zero counts, the creation roster) are enforced, the preview and body bytes cohere, an impossible late-without-assignment flag refuses, and a Channel association mismatch against the receipt's scope is an integrity refusal. A malformed stored receipt is a body-free `STORAGE_INTEGRITY_ERROR`, never absence and never a fresh execute. Beyond shape, a hash-matching retained receipt must be this request's original outcome: `checkRetainedSummaryAgainstRequest` compares the input-known sender, kind, assignment, relay target, the three verbatim context fields with their null-versus-empty distinction, the accepted byte count, and the once-prepared preview against the retained summary, and `checkRetainedCreationAgainstRequest` compares the known main handle, normalized title, and creator provenance against the stored creation view. The submission comparison runs on both the mutation path and the read-only inspection, whose recovery seam prepares the same bounded preview from the once-accepted input before any inspection; creation supports normal retained-key replay only. A contradiction is a body-free integrity refusal; a legitimately different request keeps its `IDEMPOTENCY_CONFLICT`, and an honest historical receipt still replays after close, deactivation, or handling, because the comparison is against the original request's input and never against current state. Input-unknowable fields — the message id, timestamps, the sender handle, and the insertion-frozen late flag — are not checked against current state. The replay-only inspection samples its lookup Clock inside the consistent captured read immediately before the receipt lookup — a capture that took time cannot revive an expired receipt, and expiry equality stays expired — and its original-input validation keeps parity with the normal submit path, including the relay-target required-exactly-on-relay rule and the full nonblank proof over a spool original. The public creator kinds are exactly `registered_project`, `unregistered_workspace`, and `user` — a `system` actor cannot create a Channel, and the User creator carries a null id. A participant handle is a single line of 1 to 64 control-free scalars whose only empty value is the empty string: whitespace-only and lone-BOM handles are byte-exact nonempty identities, distinct under uniqueness and lookup, while titles and labels keep their trimmed rules and the body keeps its nonempty-after-trim rule.
