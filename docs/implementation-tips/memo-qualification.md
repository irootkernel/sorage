## Combined recovery and storage checks

The compiled backup journey creates open, done, dismissed, edited and reopened Memos across archived and unbound Projects. It independently hashes published bytes, compares two unchanged exports, restores into an empty home, and compares complete Memo fields and decoded metadata events by stable identity. Database insertion order and JSON object-key order are not domain state. The source receipt inventory is nonempty while the restored inventory is empty. A second restore refuses the populated target without changing it.

The format-1 case uses the retained legacy serializer and a pinned legacy manifest shape, then drives the current native restore command without changing source bytes. It qualifies legacy-reader compatibility, not an execution of an old product binary. Native corruptions cover changed bytes, removed final LF, noncanonical JSON with a recomputed digest, missing digest, parent-path alias and symlink. Verify, dry-run and actual restore all reject them; target rows, configuration and Vault identity remain unchanged. Broader malformed inventory, event, special-file and interruption cases remain with the storage owner's real integration tests rather than being replaced by this smaller public journey.

The final qualification reuses the skill walkthrough only while its exact skill bytes and relevant CLI behavior remain unchanged. Its nine fixture cases included config-based Installation observation before new mutations, exactly one execution of each requested fixture work item, no body-triggered side effects, and replay-only inspection without changes to expired/restored inventories. A mixed-version exploratory walkthrough is excluded from that evidence. Browser tests independently cover unknown requests after snapshots both before and after the original operation, storage failures, explicit abandonment and late responses, including edits made while the original response is pending.

## Compatibility and assurance limits

CLI/HTTP additions are non-breaking for existing Handoff clients; existing Handoff output goldens and routing/decoding/replay behavior remain covered. The Memo body-file error and Memo-specific recovery guidance are additive. Migration 7 is append-only and preserves populated pre-Memo state and valid operational receipts in place. Snapshot format 2 is an explicit new generation that older format-1 readers cannot consume; the new reader retains format-1 support. Restore excludes receipts in either format. There is no supported in-place database downgrade, automatic conversion of Handoffs, live synchronization, or Memo purge. No product version, installation, publication or rollout is allocated by this qualification.

| Boundary | Evidence and remaining limit |
|---|---|
| Restart durability | Actual CLI, daemon and browser process restarts are exercised. Physical OS reboot, crash and power-loss qualification are unperformed. |
| Input and accessibility | Actual browser Korean text, composition events, keyboard focus/labels, responsive layouts and exact newlines are exercised. A physical OS input-method session is unperformed. |
| Project resolution | Native resolution, explicit unbound scope and move/rebind/rename paths are exercised. Duplicate bindings are injected for ambiguity guidance because SQLite normally prevents them; physical APFS firmlink/bind-mount qualification is unperformed. |
| Upgrade operations | Current native backup/restore command drills and legacy snapshot fixtures are exercised. The documentation drill does not run an old binary or an interactive LaunchAgent upgrade on the user's installation. |
| Skill behavior | Nine independently observed requests qualify a frozen skill and actual CLI. They cannot guarantee arbitrary future assistant behavior; original recovery time/Installation continuity are fixture preconditions and expiry is injected locally. |
| Installation and external state | All acceptance homes, Vaults and remotes are temporary. The developer's real home and external ecosystem repositories are outside these checks; no release or live rollout is implied. |
