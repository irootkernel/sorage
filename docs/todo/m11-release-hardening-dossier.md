# M11 Release Hardening and Regression Coverage Dossier

[EPIC-025](../roadmap/README.md#epic-025-m11-release-hardening-and-regression-coverage) delivers seven follow-ups for `v0.1.6`. On 2026-11-26, Master approved including all seven in the release and switching `web --json` and its consumers together. [Proposed ADR-0041](../architecture-decision-records/README.md#adr-0041-m11-release-hardening-and-regression-coverage) records the associated design. The [roadmap](../roadmap/README.md) owns lifecycle and dependencies. Retire this dossier at Epic closeout after moving enduring guidance and evidence to their canonical owners.

## Scope and compatibility

The seven findings cover Project and Vault root containment, whitespace-only Handoff body scans, missing or empty upload titles, timeline overflow, stale Web assets, narrow Web layout and Daemon and Web CLI JSON consistency. The [deferred feedback register](../deferred-feedback/README.md) retains their origin and the evidence behind the prior review. Exchange storage `Result` conversion and file `fsync` retain their existing re-entry conditions.

Use revision `dcd7ee58b344f5fa6e94dc306ae7c448821c796c` as the registration baseline. The [TASK-163 result](../implementation-tips/m11-qualification.md#71-exact-source-and-complete-automated-gate) identifies the earlier measured product revision and executable. The new candidate preserves the existing SQLite schema, Vault layout, backup format 5 with Format 1–5 readers, short Artifact IDs, and the 59 MCP tools and their schemas. Run product verification with the managed toolchain and isolated temporary `SORAGE_HOME` installations. Use a unique physical directory under `/tmp` when a gate needs scratch space.

### TASK-169 — Correct Project and Vault root containment

Introduce a shared root-safe, segment-aware path containment helper where `/` is an ancestor of every absolute descendant path and ordinary sibling prefixes (`/a` vs `/a-b`) never falsely match. Apply it to `checkVaultContainment` and `checkExternalSource` (`packages/core/src/content/import-policy.ts`), `moveVault` self-overlap (`packages/core/src/vault/vault-commands.ts`), sender downgrade detection (`resolveSenderIdentity` in `packages/core/src/project/workspace-identity.ts`, including `cwd === "/"` under `PRJ-019`), `bindings.nested` (`packages/adapters/src/doctor-checks-bindings.ts`), `absentRealPath` root joining (`packages/adapters/src/project-command-ports.ts`), and binding commit-time revalidation across `createProjectWithBinding`, `addBinding` and `replaceBinding` (`packages/adapters/src/projects.ts`). Reject add, bind and rebind targets when either the workspace contains the Vault or the Vault contains the workspace using `VAULT_CONTAINMENT`.

Keep containment checks strictly separate from legacy `/` authority. A pre-existing invalid `/` binding row in SQLite remains visible in `project list` and `project show` and explicitly repairable via `project rebind` or `project unbind` (preserving Project ID, history and unbind protections), but MUST NOT gain implicit authority over descendant workspaces in `resolveWorkspaceActor`, `resolveSenderIdentity`, `revalidateSenderAtCommit` (including the `unresolvedRoot` check that currently matches `/` via `atOrBelowRootSafe`), or `findBindingConflict`. Preserve Git common-directory precedence, deepest valid directory matching and same-depth ambiguity.

Run `bun run test:unit -- import-policy.test.ts project-commands.test.ts project-resolution.test.ts workspace-identity.test.ts vault.test.ts` and `make build` followed by `bun run test:int -- cli-projects.int.test.ts projects.int.test.ts vault-move.int.test.ts`. Require exit 0. Cover `/` containing a temporary Vault, Vault containment in the opposite direction, `moveVault` targeting `/`, unregistered send from `/` triggering `SENDER_IDENTITY_DOWNGRADE`, ordinary sibling paths with a shared string prefix, rejection without a partial binding, and a legacy `/` binding fixture proving zero implicit descendant authority alongside explicit successful repair and stable historical identity.

### TASK-170 — Eliminate synchronous Handoff body rescans and cover title validation

Keep `MultipartEnginePolicy.onComplete` (`apps/daemon/src/multipart-engine.ts`) synchronous and shared with Memo multipart untouched. Eliminate `utf8EmptyAfterTrim`'s synchronous `readSync` rescan on the daemon request callback in `apps/daemon/src/upload.ts` using either: (a) incremental streaming UTF-8 validation (`TextDecoder("utf-8", { fatal: true })`) and non-whitespace tracking inside the `body` push-sink (`write`/`finish`), storing the outcome for evaluation inside `onComplete` so there is zero disk re-read and exact error precedence is preserved; or (b) bounded asynchronous file reads executed in `consumeMultipartUpload` after `await streamMultipart(...)` settles, closing the handle and invoking `result.cleanup()` on refusal. Preserve UTF-8 decoder and `trim()` behavior, established error precedence, file-upload filename fallback, size limits and spool cleanup ownership before dispatching a Handoff mutation or recording its receipt. Reuse the existing `CONFIG_INVALID` response for whitespace-only body text and for body-only requests with an omitted or empty title.

Run `bun run test:unit -- upload.unit.test.ts multipart-engine.unit.test.ts`, `make build` followed by `bun run test:int -- upload.int.test.ts`, and `bun run test:contract -- upload-envelopes.contract.test.ts`. Require exit 0. Include a large in-limit whitespace-only body, valid split multi-byte UTF-8 input across chunk boundaries, malformed or aborted multipart handling, missing and empty title cases creating no Handoff, 413 for an oversized keyed request, and successful replay of an identical valid keyed request. Check that each refusal leaves no request spool.
